# 极简双按钮体验重构方案

> 状态：**已确认并实现（v1.4.0）**，分支 `feature/minimal-two-button-ui`
> 日期：2026-09-06（确认并实施）
> 关联版本：v1.3.0 → 目标 v1.4.0
> 关联文档：`配置管理体验重构与备份体系需求方案.md`、`插件精简重构记录.md`、`架构设计.md`

---

## 1. 问题：现在的体验为什么"奇怪"

用户的心智模型只有一句话：**把配置备份出来，把配置导回去**。
但插件目前要求用户理解的概念远多于此。盘点现状：

### 1.1 入口数量：1 个按钮点开后是 6 个按钮，点完还有下一层

```
顶部菜单「配置管理」(1 个入口)
 ├─ 备份
 │   ├─ 立即备份（全量 Portable）        → 弹窗（4 个字段）
 │   └─ 备份记录（恢复入口）             → 弹窗（列表，每项又有恢复/解压/打开位置）
 ├─ 迁移
 │   ├─ 迁移到新版                      → 弹窗（来源模式/配置包/目标exe/附加目标/组件勾选/高级）
 │   └─ 导出配置包                      → 弹窗（输出目录 + 5 个组件勾选）
 └─ 维护
     ├─ 打开报告
     └─ 清理迁移残留                    → 弹窗
```

用户想做的每一件事都要**先做一道选择题**：备份还是迁移？导出包还是全量？恢复还是解压恢复？——这些是开发者的分类，不是用户的分类。

### 1.2 概念数量：三种"包"、三种"恢复"，用户无法区分

| 概念 | 实际用途 | 用户视角的问题 |
|------|----------|----------------|
| 全量 Portable 备份（zip） | 整个 portable 目录打包，降级恢复用 | "配置包"和"全量备份"有什么区别？我该用哪个？ |
| 跨版本配置包（profile） | 跨版本迁移用 | 名字叫"导出配置包"，和"立即备份"像同一个东西 |
| 迁移前备份（recovery） | 迁移失败回滚用 | 系统自动产生的，但和前两个混在同一个"备份记录"列表里 |

"导入"同样分裂：恢复入口在"备份记录"里、跨版本导入在"迁移到新版"里（还要先切"配置来源"模式）、解压恢复又是第三个 operator。**用户找不到一个叫"导入"的按钮。**

### 1.3 路径负担：核心流程暴露了 3~4 个路径字段

- 打包弹窗：Portable 文件夹、输出目录、版本号、排除缓存
- 迁移弹窗：配置包路径、目标 blender.exe、输出目录……
- 其中 **"Portable 文件夹"这个概念本身就是插件视角的**——用户根本不该需要知道自己的 Blender 装在哪。

### 1.4 一个隐藏矛盾：迁移功能 Windows-only，但本机是 macOS

`mmy.migrate_to_blender` 和恢复流程明确 `sys.platform != "win32"` 直接报错。
当前主力机是 macOS，意味着"迁移到新版"这个最重的功能对用户来说**点了就是报错**，却占据着面板最显眼的位置。

## 2. 目标：两个按钮的心智模型

```
┌──────────────────────────────────────┐
│ 顶部菜单栏：  [导出配置]  [导入配置]   │
└──────────────────────────────────────┘
```

### 2.1 「导出配置」—— 一键，无弹窗（推荐）或极简确认

点击即用**智能默认值**执行，全程不问任何问题：

1. 自动保存当前偏好（现有逻辑已具备）
2. 采集当前 Blender 全部配置（偏好/快捷键/启动文件/插件/扩展，组件用上次记忆或安全默认值）
3. 输出到记忆目录（默认桌面），文件名自动生成
4. 状态栏显示进度与已用时长（异步任务机制已有），完成后报出完整路径
5. 后台自动清理超过 N 份的旧导出（防堆积，可选）

**路径去哪了**：完全融合进"路径记忆"——第一次使用时若从未设置过，导出前弹一次极简询问或直接落桌面并在报告中告知"以后都存这里，可在偏好设置修改"。之后永远不再问。

**组件勾选去哪了**：默认全选安全项（预设含、数据文件/启动脚本/历史不含，与现状一致）。需要调整时走偏好设置里的默认项（已有 `migration_include_*` 属性），而不是每次弹窗都问。

### 2.2 「导入配置」—— 一个入口吃掉所有"恢复/迁移"场景

点击后打开**文件选择器，默认定位到上次导出目录**（而非让用户手填路径），选中任意本插件产生的文件后**自动识别类型**：

| 识别结果 | 后续流程 |
|----------|----------|
| 跨版本配置包 | 展示摘要（来源版本/创建时间/组件）→ 自动列出本机可用目标 Blender → 预检确认页（复用现有两阶段机制） |
| 全量 Portable 备份 | 展示摘要 → 确认解压目标（默认给推荐路径） |
| recovery.json | 提示"这是迁移自动产生的回滚点"→ 确认恢复 |

关键体验点：
- **不再让用户区分"恢复"和"迁移"**——选对文件，插件自己知道该干什么
- 目标 Blender 自动探测（`find_blender_executables` 已有），不再要求用户手选 exe
- 预检确认页保留（这是安全网，不省）

### 2.3 降级进二级位置的现有功能

不删除，只挪窝，挂在**插件偏好设置**（或总入口弹窗的一个折叠"更多"区）：

- 备份记录列表（也可以由"导入配置"的文件浏览器自然替代，见 §4 问题3）
- 打开迁移报告
- 清理迁移残留
- 版本号覆盖、排除缓存、审计超时等高级参数
- 每周自动打包

## 3. 改造范围（代码层面预估）

| 模块 | 改动 |
|------|------|
| `ui.py` | 重写：顶部菜单从 1 个总入口改为 2 个直达按钮（`mmy.export_config`、`mmy.import_config`）；总入口弹窗删除或降级 |
| `migration.py` | `MMY_OT_ExportMigrationProfile` 改造为一键版（无 props dialog，默认值直出）；新增统一导入 operator：文件选择器 + 类型识别 + 分发到现有恢复/迁移 operator；目标 exe 自动探测默认值 |
| `preferences.py` | 新增"导出保留份数"等少量属性；现有 `migration_include_*` 保留，作为导出默认项 |
| `migration_core.py` | 基本不动（两阶段迁移、回滚、报告机制原样保留） |
| `pack.py` / 版本号 | bl_info → 1.4.0 |

风险低：所有底层能力（快照、预检、回滚、worker）不动，只动交互层。

## 4. 需要拍板的问题（讨论重点）

**问题 1：导出格式要不要统一？**
现状是"全量 Portable zip"和"跨版本配置包"两种导出并存。
推荐：**主流程只保留跨版本配置包一种**（它能被"导入配置"完整消费，体积也更小），全量 Portable 打包降级为偏好设置里的高级选项，服务"整机搬迁/降级"这种少见场景。

**问题 2：导出是纯一键，还是保留一个轻量确认弹窗？**
推荐纯一键（信息在状态栏和完成报告中给足）；如果你担心误触或想每次确认输出位置，可改为"点击 → 只有一个确认按钮的迷你弹窗"。

**问题 3：「备份记录」列表要不要保留？**
推荐：**不保留为独立入口**。"导入配置"的文件浏览器本身就承担"回到旧版本"的场景（打开上次导出目录、按文件名时间排序）。recovery 回滚点可以在导入时识别。若你习惯"列表式找回"，可以把它挪进偏好设置。

**问题 4：macOS 支持的优先级？**
迁移（导入配置包）目前 Windows-only，而你在 macOS 上用。
推荐：本次重构把"导入配置"在 macOS 上做到**恢复全量备份可用**，跨版本迁移保持 Windows-only 并在 UI 上明确标注（而不是点击后报错）；macOS 迁移支持单独立项。

**问题 5：顶部菜单形态。**
两个按钮直接平铺在顶栏（最直达，占两个位置），还是保留一个「配置」下拉菜单内含两项（省空间，多一次点击）？
推荐：平铺两个按钮，符合"极简"初衷。

## 5. 实施分期建议

1. **第一期（本方案核心）**：双按钮 + 一键导出 + 统一导入 + 类型自动识别；高级功能收进偏好设置。
2. **第二期（可选）**：旧备份自动清理、导出完成通知增强（结果摘要面板）、导入向导按预检结果给"一键最优路径"建议。
3. **另行立项**：macOS 跨版本迁移支持。

---

## 6. 讨论结论记录

2026-09-06 用户确认计划，5 个决策点均采纳推荐方案：

1. **导出格式统一**：主流程只保留跨版本配置包一种；全量 Portable 打包降级为偏好设置「维护与高级」里的高级选项（整机搬迁/降级场景用）。
2. **导出纯一键**：无弹窗，默认值直出（组件取偏好设置默认项，启动脚本仅在偏好中显式开启时包含），完成后报告完整路径。
3. **备份记录列表**：不保留独立入口，挪入偏好设置「维护与高级」；"导入配置"的文件浏览器承担回到旧版本的主场景。
4. **macOS 支持分级**：导入流程在 macOS 上支持全量备份恢复与回滚点恢复；跨版本迁移保持 Windows-only，迁移弹窗与导入报错均明确提示，不静默失败。macOS 迁移支持另行立项。
5. **顶栏形态**：两个按钮平铺（`导出配置` + `导入配置`）。
