## 背景

用户核心需求变更：从「精细化备份/导入/导出配置」变为「直接打包整个 Blender `portable/` 文件夹用于多机迁移」。

## 变更内容

### 1. 重构 `pack.py` → 打包 `portable/` 文件夹

| 功能 | 实现方式 |
|------|------------|
| 动态路径选择 | 改为 Blender 原生弹窗（`invoke_props_dialog`），不再依赖 tkinter |
| 自动版本检测 | 三层方案：父目录名 → 子目录名 → 手动输入 |
| 时间戳命名 | `datetime.now().strftime("%Y%m%d_%H%M")` |
| 输出路径 | 用户选目录，文件名自动生成：`Blender_Portable_v{版本}_{时间戳}.zip` |
| 文件排除 | 默认排除 `__pycache__/*.pyc/*.git` 等 9 类，可勾选「不排除」 |
| 打包模式 | 默认 `ZIP_STORED`（仅存储不压缩，快 5-10x），可加 `--compress` 启用压缩 |

- `ui.py` 直接 `Path(__file__).parent / "pack_script.py"` 找到脚本
- 用户无需配置路径，开箱即用
- 路径选择走 Blender 原生文件浏览器（`DIR_PATH` / `FILE_PATH`）

**原因**：

- `record()` 调用缺逗号：`AddonLoadRecord(name elapsed, error)` → `AddonLoadRecord(name, elapsed, error)`

**修复**：

- 补上逗号

- 添加数据持久化（保存到 `.mmy_timer_data.json`，重启后可查看上一次数据）
- 增强诊断日志（每步操作都输出 `[MMY]` 前缀日志）

## 迭代修复的问题

### 问题 1：tkinter 依赖导致打包按钮无反应

**现象**：点击「打包导出」按钮后，没有任何反应，ZIP 文件未生成。

**根因**：Blender 自带的 Python 没有 `tkinter` 模块。`pack_script.py` 第 15 行 `import tkinter` 导致脚本启动时直接崩溃，且没有任何错误提示。

**修复**：
- 移除 `pack_script.py` 顶层 `tkinter` import，改为函数内按需导入
- 支持命令行参数：`pack_script.py <portable_path> [output_path]`
- `ui.py` 的路径选择改为 Blender 原生弹窗（`invoke_props_dialog`），不再需要 tkinter

### 问题 2：打包按钮找不到 `pack.py`

**现象**：点击按钮报错：`找不到 pack.py: C:\BlenderAPP\Blender5.1\portable\scripts\addons\pack.py`

**根因**：`Path(__file__).parent.parent` 在 Blender 中指向 `C:\BlenderAPP\Blender5.1\portable\scripts\addons\`，不是 Git 仓库。

**修复**：
- 将 `pack.py` 复制为 `mmy_pack_config/pack_script.py`（内嵌到插件包内）
- `ui.py` 直接 `Path(__file__).parent / "pack_script.py"` 找到脚本
- 用户无需配置路径，开箱即用

### 问题 3：文件名错误（`(1)`、`下载 (1)`）

**现象**：导出的 ZIP 文件名不正确，出现 `(1)` 后缀或目录名作为文件名。

**根因**：用户在 Blender 弹窗里选的「输出路径」是一个**目录**（如 `E:\下载`），但代码把它直接当成了文件名。`get_unique_output_path()` 发现这个"文件名"已存在，就重命名为 `(1)`。

**修复**：
- `ui.py` 的输出字段从 **FILE_PATH** 改为 **DIR_PATH**（选目录）
- 文件名由代码自动生成：`Blender_Portable_v5.1.0_20260622_xxxx.zip`
- `pack_script.py` 新增 `normalize_output_path()` 函数统一处理各种输入

### 问题 4：打包速度慢

**现象**：打包 7542 个文件需要几分钟。

**根因**：全部用 `ZIP_DEFLATED`（压缩算法）处理，每个文件都要做压缩计算。`portable/` 里大部分是 `.pyc`、`.blend`、图片等已压缩或不可压缩的文件，压缩收益很小但耗时巨大。

**修复**：默认改为 **ZIP_STORED**（仅存储不压缩）：
- 7542 个文件从可能几分钟降到几秒
- 可通过 `--compress` 参数启用 `ZIP_DEFLATED` 压缩

### 问题 5：解压后文件数目对不上

**现象**：导出 ZIP 后解压，对比 Blender 软件目录里的配置文件夹，发现数目对不上。

**根因**：`pack_script.py` 在打包时静默排除了 9 类文件（`__pycache__/*.pyc/*.git` 等），但控制台输出不够醒目，用户不知道哪些被跳过了。

**修复**：
- `should_exclude()` 改为返回 `(是否排除, 排除原因)` 元组
- `pack_portable()` 统计排除原因分布，打包完成后打印详细摘要
- 新增「排除缓存/临时文件」勾选项（默认勾选），取消勾选则传 `--all` 参数，ZIP 包含所有文件（1:1 完全一致）

## 最终方案总结

### 文件结构

```
MMY-Blender-Configure/
├── pack.py                          # 外部独立运行：打包 portable/ 文件夹
├── mmy_pack_config/
│   ├── __init__.py                 # 插件注册
│   ├── ui.py                      # 菜单栏「打包导出」按钮
│   ├── preferences.py              # 偏好设置（耗时监控 + 打包设置）
│   ├── addon_timer.py             # 插件加载耗时监控
│   ├── utils.py                   # Portable 模式检测
│   └── pack_script.py             # 内嵌打包脚本（供 ui.py 调用）
├── 开发文档/
│   └── 插件精简重构记录.md
└── releases/                       # 插件本身打包输出目录
```

### 使用流程

**打包 `portable/` 文件夹（两种方式）**：

1. **从 Blender 内**：
   - 点击顶部菜单栏「打包导出」
   - 填路径 → 点确认
   - 弹出控制台窗口显示打包进度
   - ZIP 出现在输出目录

2. **从外部独立运行**：
   ```bash
   # 交互模式（弹窗选择路径）
   python pack.py
   
   # 命令行模式
   python pack.py D:/Blender/portable D:/Desktop/output.zip
   
   # 不排除任何文件（1:1 完全一致）
   python pack.py D:/Blender/portable --all
   ```

**打包插件本身**（符合 AGENTS.md 自动打包机制）：
```bash
python pack.py   # 无参数时，打包 mmy_pack_config/ 到 releases/
```

## 已知限制

### 1. 插件耗时监控的「早期加载」问题

**现象**：重启 Blender 后，大部分插件显示为「早期加载」，耗时都是 `--`。

**原因**：monkey-patch `_addon_utils.enable` 注入时机太晚——我们的插件本身也是被 `_addon_utils.enable()` 加载的，等我们的 `register()` 执行时，大部分插件已经加载完了。

**缓解措施**：
- 数据持久化：监控数据保存到 `.mmy_timer_data.json`，重启后可查看上一次的数据
- Fallback 扫描：2 秒后扫描已加载但未捕获的插件（记为"早期加载"，耗时 --）

**彻底解决方案**（未实现）：
- 将我们的插件打包为 Blender 的「启动脚本」（`startup/blend.py`），在所有插件之前执行
- 或使用 Blender 的 `--python` 命令行参数，在启动早期注入监控代码

### 2. `addon_timer.py` 在 Blender 未来版本中的兼容性

`bpy.utils._addon_utils.enable` 是**私有 API**，可能随版本变化而失效。

当前已加 `try-except` 保护，失败只打印警告不崩溃。如果未来失效，需要：
- 监控 Blender 更新日志，及时调整 monkey-patch 方式
- 或改用 Blender 官方的插件加载钩子（如果存在）
