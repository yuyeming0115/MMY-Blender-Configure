# 应用模板（bl_app_templates_user）备份迁移支持方案

> 分支：`feature/app-templates-migration`
> 日期：2026-08-26
> 状态：已实现

## 一、需求背景

用户反馈：插件的备份与迁移功能未覆盖便携版目录
`C:\BlenderAPP\Blender5.1\portable\scripts\startup\bl_app_templates_user`。

该目录是 Blender **应用模板（App Templates）** 的用户级存放位置，每个模板为一个子目录，内含 `__init__.py` 与 `startup.blend`（界面布局与启动配置），属于**用户资产**，性质接近 presets。

## 二、现状分析

原实现对 `scripts/startup` 做整目录递归打包（`_profile_sources()`），因此**功能上模板已被隐性覆盖**——但入口存在设计缺陷：

| 问题 | 说明 |
|------|------|
| 开关捆绑错位 | 模板藏在「🔴 高风险·启动脚本」开关内，默认关闭，还需勾选「我已了解风险」二次确认 |
| 语义误导 | 风险警示文案针对自动执行代码（Python 脚本），而模板核心是 `.blend` 布局资产，风险等级不同 |
| 用户感知割裂 | 不读源码无法得知需勾「高风险启动脚本」才能迁移模板，本次反馈即源于此 |

## 三、方案决策

采用**独立开关方案**（用户已确认）：

1. `bl_app_templates_user` 拆为独立组件 `app_templates`，独立开关控制
2. UI 归入「🟡 谨慎（按需勾选）」组（含跨版本升级的二进制 `.blend`），脱离高风险确认流程
3. 偏好设置新增「默认包含应用模板」，与其他迁移默认项一致

## 四、实现要点

### 4.1 核心层（`migration_core.py`）

- `SourceSnapshot` 新增 `include_app_templates: bool = False` 字段
- `_profile_sources()` 返回值扩展为四元组 `(来源, 归档基路径, 组件名, 顶层排除子目录)`
- 启动脚本组件打包 `scripts/startup` 时**排除** `bl_app_templates_user` 子目录——否则两开关同开时会触发 `add_file` 的「配置快照内路径重复」校验报错
- 应用模板独立来源：`scripts/startup/bl_app_templates_user` → 归档路径 `payload/scripts/startup/bl_app_templates_user`
- **归档路径刻意与 Blender 标准模板位置一致**：恢复侧 `extract_profile()` 按路径落位即可，整体替换/审计/回滚逻辑零改动
- `_iter_regular_files()` 新增 `exclude_top_dirs` 参数实现顶层子目录排除
- 快照排除规则不误杀模板文件：`.blend` 不在 `_SKIP_SUFFIXES`（仅 `.blend1/.blend2/.blend3` 被排除）

### 4.2 UI 层（`migration.py`）

- `_SnapshotOptionsMixin`：加载/展示/传参/保存偏好四处同步新开关；开关置于 🟡 谨慎组首位
- `MMY_OT_MigrateToBlender` 与 `MMY_OT_ExportMigrationProfile` 两个操作符各新增
  `include_app_templates` BoolProperty（名称注明目录与 `.blend` 特征）
- `_run_precheck()` 组件列表追加 `app_templates`，确认页与配置包摘要随之展示

### 4.3 偏好层（`preferences.py`）

- 新增 `migration_include_app_templates`（默认 False），跨版本迁移默认项网格中展示

### 4.4 跨版本兼容说明

模板内 `startup.blend` 为版本相关二进制，迁入更高版本后首次使用时由 Blender 自动升级——与固定组件 `config/startup.blend` 同等处理策略，无需特殊逻辑。模板的 `__init__.py` 模块级代码会在 Blender 启动扫描模板时执行，故不放入 🟢 安全组。

## 五、测试

`tests/test_migration_core.py` 新增两个用例：

1. `test_app_templates_packed_as_independent_component`
   - 仅开应用模板开关：模板 `__init__.py`/`startup.blend` 进入快照，普通启动脚本不进入
   - manifest 组件含 `app_templates` 不含 `startup_scripts`
   - `extract_profile()` 落位到标准模板目录
2. `test_app_templates_and_startup_scripts_no_duplicate_paths`
   - 两开关同开：模板文件各出现一次、无路径重复报错，普通脚本正常进入

全套 33 个测试通过。

## 六、影响面

- 恢复/迁移/审计/回滚链路：**零改动**（归档路径设计保证）
- 旧配置包（不含 `app_templates` 组件）：行为不变，兼容
- manifest `schema_version` 维持 2（新增组件仅是 components 列表新取值，向后兼容）
