# MMY Blender Configure 开发计划

## 项目概述

**插件名称**：MMY Blender Configure  
**作者**：会叫喵的鱼  
**目标版本**：Blender 4.5+  
**插件分类**：MMY-Tools  

### 核心功能
一键备份、导入、导出 Blender 配置（快捷键、软件设置、插件），并监控插件加载耗时和报错信息。

### 使用场景
- 多台电脑间同步 Blender 配置
- 升级 Blender 版本前备份配置
- 团队统一配置环境
- 排查插件加载性能问题

---

## 技术架构

### 文件结构（多文件包）

```
MMY-Blender-Configure/
├── __init__.py              # 插件入口，bl_info，注册/注销
├── operators.py             # 备份、导入、导出 Operator
├── ui.py                    # Header 按钮 + Popover 面板
├── addon_timer.py           # 插件耗时采集模块
├── preferences.py           # 插件偏好设置（备份路径等）
└── utils.py                 # 路径工具、zip 打包/解包
```

**为什么选择多文件**：
- 插件耗时监控需在启动早期注入，逻辑独立
- 备份/导入/导出涉及文件 I/O，代码量大
- 便于后续扩展配置类型

### 核心模块职责

| 模块 | 关键类/函数 | 职责 |
|------|------------|------|
| `__init__.py` | `register()` / `unregister()` | 统一注册，启动耗时采集 |
| `addon_timer.py` | `AddonTimerManager` | 记录插件加载耗时和错误 |
| `operators.py` | `MMY_OT_BackupConfig` | 备份配置到 zip |
| | `MMY_OT_ImportConfig` | 从 zip 还原配置 |
| | `MMY_OT_ExportConfig` | 导出配置到指定路径 |
| `ui.py` | `MMY_PT_ConfigPopover` | Popover 面板 UI |
| | `draw_header_button()` | 顶部菜单栏按钮 |
| `preferences.py` | `MMYConfigPreferences` | 存储勾选状态、默认路径 |
| `utils.py` | `pack_to_zip()` / `unpack_from_zip()` | zip 打包/解包 |

## 功能设计详解

### 1. UI 布局

#### 顶部菜单栏按钮
- **位置**：最左侧（使用 `TOPBAR_HT_upper_bar.prepend()`）
- **图标**：🧾 文档图标（Blender 内置 `WORDWRAP_ON` 或自定义 PNG）
- **交互**：点击弹出 Popover 面板

#### Popover 面板内容
```
┌─────────────────────────────┐
│ MMY 配置管理                 │
├─────────────────────────────┤
│ 选择配置类型                 │
│ ☑ 用户快捷键                │
│ ☑ 软件设置                  │
│ ☑ 插件                      │
├─────────────────────────────┤
│ [备份] [导入] [导出]         │
├─────────────────────────────┤
│ 插件加载耗时 ⏱              │
│ addon_a    12.3ms           │
│ addon_b    45.6ms  ⚠ ERROR  │
└─────────────────────────────┘
```

### 2. 配置备份/导入/导出

#### 备份格式：`.zip` 压缩包

```
mmy_config_20260511_143000.zip
├── manifest.json            # 元数据（版本、时间戳、包含项）
├── userpref.blend           # 软件设置 + 快捷键 + 插件状态
├── config/                  # 用户配置（bookmarks、recent-files 等）
── addons/                  # 仅当勾选"插件"时包含
│   ├── addon_a/
│   └── addon_b.py
── scripts/presets/         # 用户预设
├── scripts/startup/         # 启动脚本
├── datafiles/               # 数据文件
├── studiolights/            # 工作室灯光预设
└── extensions/              # 扩展包
```

**manifest.json 示例**：
```json
{
  "blender_version": "4.5.0",
  "created_at": "2026-05-11T14:30:00",
  "includes": ["keymap", "prefs", "addons", "config", "presets", "startup", "datafiles"]
}
```

#### 备份流程
1. 调用 `bpy.ops.wm.save_userpref()` 确保最新状态已写入磁盘
2. 从 `bpy.utils.user_resource('CONFIG')` 等 API 获取各目录路径
3. 根据勾选项收集文件：
   - keymap/prefs → `config/userpref.blend`（Blender 不分离存储）
   - addons → `scripts/addons/` 下用户安装的插件
   - config → 用户配置目录（bookmarks、recent-files 等）
   - presets → `scripts/presets/`
   - startup → `scripts/startup/`
   - datafiles → `datafiles/` + `studiolights/` + `extensions/`
4. 写入 `manifest.json`，打包为 zip
5. 保存到默认路径或用户指定路径

#### 导入流程
1. 文件选择器过滤 `.zip`
2. 解析 `manifest.json`，校验 Blender 版本兼容性
3. 覆盖前自动对现有配置做临时备份（`.mmy_temp_backup_<timestamp>.zip`）
4. 按勾选项选择性还原文件
5. 弹出提示：需重启 Blender 生效

#### 导出流程
复用备份逻辑，仅目标路径由用户指定。

### 3. 插件耗时监控

#### 方案：Monkey-patch + 兜底

**主方案**：在 `register()` 中包装 `bpy.utils._addon_utils.enable`

```python
import time, traceback

_original_enable = bpy.utils._addon_utils.enable

def _timed_enable(module_name, *args, **kwargs):
    t0 = time.perf_counter()
    error = None
    try:
        result = _original_enable(module_name, *args, **kwargs)
    except Exception as e:
        error = traceback.format_exc()
        result = None
    elapsed = time.perf_counter() - t0
    addon_timer.manager.record(module_name, elapsed, error)
    return result

bpy.utils._addon_utils.enable = _timed_enable
```

**兜底方案**：`bpy.app.timers` 启动后扫描 `sys.modules`，检测加载失败的插件。

**为什么不用启动日志**：需要用户手动配置 `--debug` 参数，普通用户不友好。

## 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 文件结构 | 多文件包 | 逻辑分离，便于维护和扩展 |
| 备份格式 | zip + manifest.json | 跨平台，可选择性还原，含元数据 |
| keymap/prefs 分离 | 不分离，统一备份 userpref.blend | Blender 本身不分离存储，强行分离需解析 blend 文件格式（复杂度过高） |
| 勾选状态存储 | AddonPreferences | Popover 关闭不丢失，随 userpref 持久化 |
| 耗时采集 | Monkey-patch + 兜底 | 精度最高，同时保证稳定性 |
| Header 按钮位置 | `prepend()` 到 TOPBAR_HT_upper_bar | 确保在最左侧 |
| 备份范围 | 支持 config/presets/startup/datafiles/studiolights/extensions | 完整还原用户工作环境，非核心目录由用户按需勾选 |
| 导入安全 | 导入前自动临时备份 | 防止误操作丢失原有配置 |
| addon_utils 路径 | `bpy.utils._addon_utils` | Blender 4.5+ 的标准路径 |

## 验证方案

### 端到端测试流程
1. **安装插件**：复制到 `scripts/addons/`，在偏好设置中启用
2. **备份配置**：
   - 修改快捷键、软件设置、安装测试插件
   - 点击"备份"，检查生成的 zip 包
   - 解压验证 `manifest.json` 和 `userpref.blend` 存在
3. **导入配置**：
   - 修改当前配置（改变快捷键）
   - 点击"导入"，选择之前的备份 zip
   - 重启 Blender，验证配置已还原
4. **插件耗时**：
   - 安装多个插件（含一个故意写错的插件）
   - 重启 Blender，打开面板
   - 验证耗时列表显示正常，错误插件标红

### 边界情况测试
- 备份路径不存在 → 自动创建目录
- 导入损坏的 zip → 提示错误，不覆盖现有配置
- 导入不同 Blender 版本的备份 → 警告但允许继续
- 磁盘空间不足 → 提示错误，清理临时文件
