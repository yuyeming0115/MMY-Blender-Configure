# 工作区级布局恢复（v1.5.0）设计文档

> 分支：`feature/workspace-donor-restore` ｜ 版本：v1.5.0 ｜ 日期：2026-10-10

## 1. 背景与问题

跨次版本迁移时（如 5.1 → 5.2），`_install_profile` 将配置包中的
`payload/config/startup.blend`（旧版窗口布局快照）整体替换目标版本的启动文件。
startup.blend 是 WorkSpace → Screen → Area 的完整静态快照，新版 Blender 的
新 UI 元素由内置默认工作区模板提供；旧快照覆盖后新 UI 永久不可见——
即用户反馈的「新版 UI 缺失」。社区标准修复法（Factory Settings 重存）治标不治本，
用户仍需手摆布局，易遗漏。

第一性原理结论（见《Blender跨版本配置迁移可行性分析报告.html》）：
配置应分层迁移。startup.blend 跨版本时不能整文件拷贝，但其中的
**自定义工作区**（用户自建的工作流空间）是用户资产，应选择性恢复。

## 2. 方案：Donor（捐赠者）模式

```
导出端（GUI，源版本）                配置包                    应用端（目标版本后台审计）
─────────────────────                ──────                    ──────────────────────────
采集工作区清单                 ┌─ payload/config/startup.blend   原子安装后：
（名称/是否默认/区域类型）  →  │   （改为"捐赠文件"，不再直接      ① 捐赠 startup 撤出到
写入 fallback/           │    安装为启动文件）                  recovery/donor_startup.blend
workspaces.json          │  └─ fallback/workspaces.json        ② 目标原 startup 恢复
                         └─ manifest.workspaces 元数据          （copy2，保持回滚完整性）
                                                              ③ 后台审计时：
                                                                read_homefile 载入目标布局
                                                                libs.load 追加"自定义工作区"
                                                                save_as_mainfile 写回
```

### 2.1 策略判定（纯函数 `plan_startup_mode`，可单测）

| 条件 | 策略 | 说明 |
|---|---|---|
| 源/目标 主.次版本相同（如 5.1.0→5.1.3） | `legacy` | 整文件安装，100% 保真（含自定义布局） |
| 配置包无工作区清单（v1.4 及更早的包） | `legacy` | 向后兼容，维持旧行为 |
| 跨次版本且清单存在 | `donor` | 保留新版默认工作区，仅移植自定义工作区 |

### 2.2 关键设计决策

1. **默认工作区名单硬编码**（FACTORY_WORKSPACE_NAMES）：Layout/Modeling/… 等
   出厂工作区是新版 UI 的载体，一律不移植，即使旧版里被改过布局。
2. **自定义工作区整空间追加**：`bpy.data.libraries.load(donor, link=False)` 追加
   Workspace ID 及其 Screen。旧数据经 Blender 读取时自动 do_versions 升级，
   比拷贝文件更可靠；新增 UI 元素不出现是可接受的（自定义工作区本来就是用户自建）。
3. **失败不阻断**：工作区恢复是附加价值，任何异常只记入报告 warnings，
   不触发整次迁移回滚；且仅在确认追加成功后才 save_as_mainfile，
   中途失败不污染目标启动文件。
4. **回滚完整性**：donor 文件 move 到 recovery_dir（外部目录，不影响回滚）；
   目标原 startup 用 `shutil.copy2` 恢复（保留 old_root 原样供回滚）。
5. **manifest 不加 schema 版本**：SCHEMA_VERSION 保持 2，新增 `workspaces` 可选键，
   v1.4 旧包因无该键自动走 legacy，新旧代码互认。

## 4. 验收标准

- 同主.次版本迁移行为与 v1.4 完全一致（legacy 路径不触碰）。
- v1.4 旧配置包导入行为与 v1.4 完全一致。
- 5.1 → 5.2 迁移后：目标默认工作区为新版布局（新 UI 完整），
  源端自定义工作区出现在标签栏，迁移报告列出恢复/跳过明细。
- 审计失败回滚后目标目录与迁移前逐字节一致（含 startup.blend）。

## 5. 已知限制

- 默认工作区内用户自定义的区域切分（如 Modeling 的四分屏）不保留——
  这是保留新版 UI 的代价，报告与确认页明示。
- 自定义工作区内的区域布局为旧版快照（经内核升级），新版在该工作区内的新 UI 不出现。
- Blender 后台模式 `read_homefile` 行为若因版本变动失效，降级为记录 warning。
